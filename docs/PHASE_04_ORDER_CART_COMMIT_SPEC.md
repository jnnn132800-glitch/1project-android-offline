# ข้อกำหนดและการตรวจสอบระบบรับรายการ ตะกร้า หน้าตรวจทาน และ Atomic Commit (Phase 04)

> **สถานะใน Container ปัจจุบัน**: `BUILD_NOT_RUN` เนื่องจากสภาพแวดล้อม Container ไม่มี JDK, Android SDK และ Gradle จึงต้องรัน `./gradlew testDebugUnitTest assembleDebug` ใน Android Studio บนเครื่องพัฒนา

---

## 1. สิ่งที่ส่งมอบใน Phase 04 (ตาม `05_UI`, `04_SPEC` และ `06_DECISIONS`)
1. **หน้าจอรับรายการ 3 แท็บ (`OrderEntryScreen.kt` & `OrderEntryViewModel.kt`)**:
   - **แท็บ 1 กรอกเอง (Manual)**: กรอกเลข 2 หลัก (`00–99`), เลือกด้าน (`บน`, `ล่าง`, `บน+ล่าง`), ตัวเลือกกลับเลข (`Reverse Union`) และระบุยอดเงินต่อเลข
   - **แท็บ 2 เลือกหลายเลข (Grid `00–99` ขนาด `10×10`)**:
     - ปุ่ม **เลือกทั้งหมด (100)**, **ล้างที่เลือก**, **Undo ย้อนกลับ**, **กลับเลขที่เลือก**
     - ตัวเลือกเลขหลัก `0–9` พร้อมปุ่ม **รูดหน้า (+10 เลข)**, **รูดหลัง (+10 เลข)**, **19 ประตู (+19 เลข)**
     - แสดงจำนวนเลขที่เลือกและคำนวณจำนวนรายการก่อนเพิ่มลงตะกร้า
     - มีปุ่ม **"ขยายเต็มจอ (สำหรับจอแคบ)" (`ExpandedGrid10x10Dialog`)** รองรับหน้าจอมือถือขนาดเล็กตามข้อกำหนด `05_UI`
   - **แท็บ 3 วางข้อความ (Paste Text)**:
     - ใช้ `PasteBatchParserAndQuoteHasher.parsePasteBatchStrict` หากมีบรรทัดผิดแม้จุดเดียวจะ **บล็อกทั้งชุด (`BlockedBatch`)** พร้อมแสดงเลขบรรทัดและสาเหตุภาษาไทยโดยไม่ตัดบรรทัดที่ผิดทิ้งเงียบๆ (`D03`)
2. **ตะกร้าในเครื่อง (Durable Cart — ไม่ใช่การจองวงเงิน)**:
   - แสดงป้ายแจ้งเตือนชัดเจนว่าตะกร้าไม่ใช่การจองวงเงิน (`D04`)
   - แยกแสดง **จำนวนเลขไม่ซ้ำ (`Distinct Numbers`)**, **จำนวนรายการ (`Line Count`)** และ **ยอดซื้อรวม**
   - รองรับการแก้ไขยอดเงินรายบรรทัด, ลบรายบรรทัด, และล้างตะกร้าทั้งหมดพร้อมกล่องยืนยัน (`Confirm Dialog`)
3. **หน้าตรวจทาน (Review) และการยืนยันบันทึกบิลแบบ Atomic Commit**:
   - แสดงรหัสงวด, รุ่นนโยบายที่ผูกกับใบตรวจทาน, อัตราจ่ายและยอดจ่ายคาดการณ์รายบรรทัด (`HALF_UP`), และยอดรวม
   - หากรุ่นนโยบายเปลี่ยนก่อนกดยืนยัน จะแสดง **คำเตือนนโยบายเปลี่ยนแปลง (`Policy Change Warning`)** และบังคับให้คำนวณใบตรวจทานใหม่ก่อนยืนยัน
   - หน้าสำเร็จ (`CommittedBillSuccessCard`) จะแสดงก็ต่อเมื่อได้รับ `committedBillId` และ `humanBillCode` ที่บันทึกใน Room Transaction สำเร็จแล้วเท่านั้น
   - มีส่วน **"ตรวจสอบ Operation เดิม"** (`verifyOrRecoverPreviousOperation`) สำหรับกู้คืนใบเสร็จจาก `durable_operations` กรณีแอปถูกปิดกะทันหัน (Process Death) หรือผู้ใช้ไม่แน่ใจผลการบันทึกก่อนหน้า
